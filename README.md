
# PassaduAIagent

ชุดไฟล์อ้างอิงและกฎการทำงานสำหรับสร้าง AI assistant ด้านการจัดซื้อจัดจ้างและการบริหารพัสดุภาครัฐของไทย

โปรเจกต์นี้ตั้งใจทำให้ AI ตอบคำถามด้านพัสดุโดยยึดตัวบทจริงเป็นหลัก ไม่แต่งข้อกฎหมายเอง และอ้างอิงกลับไปยังไฟล์ Markdown ที่ตรวจสอบได้

## เป้าหมาย

- ทำให้กฎหมายและระเบียบด้านพัสดุภาครัฐอยู่ในรูปแบบ Markdown ที่ AI ใช้งานได้ง่าย
- สร้างกฎการตอบที่บังคับให้ AI อ้างอิงมาตรา/ข้อจากไฟล์จริง
- แยกคำตอบเชิงกฎหมายออกจากการวินิจฉัยเบื้องต้น
- ลดการเดา ลด hallucination และเพิ่มความโปร่งใสของคำตอบ
- วางฐานสำหรับพัฒนา agent, retrieval script, และ evaluation set ในอนาคต

## ไฟล์สำคัญ

| ไฟล์ | หน้าที่ |

| `reference/law/rbb60.md` | ระเบียบกระทรวงการคลังว่าด้วยการจัดซื้อจัดจ้างและการบริหารพัสดุภาครัฐ พ.ศ. 2560 |

## หลักการออกแบบ

Pasadu ถูกออกแบบให้ตอบแบบผู้ช่วยงานพัสดุที่รอบคอบ:

1. อ่านคำถามและแยกประเภทประเด็นก่อนตอบ
2. เลือกไฟล์อ้างอิงให้ถูก: พระราชบัญญัติหรือระเบียบ
3. ค้นหามาตรา/ข้อที่เกี่ยวข้องจากไฟล์จริง
4. ตอบโดยแยก “ตัวบท”, “วินิจฉัย”, และ “ข้อควรตรวจเพิ่ม”
5. ถ้าข้อมูลไม่พอ ให้ถามกลับก่อนสรุป
6. ถ้าไม่พบใน reference ให้บอกว่าไม่พบ ไม่เดาแทนตัวบท

## การใช้งานที่ตั้งใจไว้

ใช้ repo นี้เป็นฐานสำหรับ AI assistant ที่ช่วย:

- ตอบคำถามเกี่ยวกับการจัดซื้อจัดจ้างภาครัฐ
- อธิบายมาตราและข้อระเบียบด้วยภาษาที่ใช้งานได้จริง
- ชี้แหล่งอ้างอิงจาก `prb60.md` และ `rbb60.md`
- วินิจฉัยปัญหาเบื้องต้นจากข้อเท็จจริงที่ผู้ใช้ให้
- ถามกลับเมื่อข้อมูลสำคัญยังไม่ครบ
- ช่วยเจ้าหน้าที่จัดลำดับประเด็นก่อนตรวจเอกสารหรือดำเนินการต่อ

- Persona/rules: มี `pasadu.md` แล้ว
- Search/retrieval script: ยังไม่ได้จัดทำ
- Evaluation set: ยังไม่ได้จัดทำ

## ข้อจำกัด

โปรเจกต์นี้เป็นฐานข้อมูลอ้างอิงและกฎการตอบสำหรับ AI assistant ไม่ใช่คำวินิจฉัยทางกฎหมายอย่างเป็นทางการ

คำตอบที่ได้จาก AI ควรถูกตรวจสอบกับตัวบท หน่วยงานเจ้าของอำนาจ หรือเอกสารราชการต้นฉบับก่อนนำไปใช้ในกรณีที่มีผลทางกฎหมาย งบประมาณ สัญญา หรือความรับผิดของเจ้าหน้าที่

## Roadmap

- เพิ่ม script สำหรับค้นหามาตรา/ข้อจากไฟล์ reference
- เพิ่ม citation checker เพื่อตรวจว่า AI อ้างมาตรา/ข้อจริงหรือไม่
- สร้างชุดคำถามทดสอบสำหรับ procurement QA
- เพิ่มตัวอย่างคำถามและคำตอบที่ดี
- ทดลองทำ agent runtime ที่ใช้ `SKILL.md` และ `pasadu.md` เป็นฐาน

## Retrieval scripts

สคริปต์ชุดแรกอยู่ใน `scripts/pasadu/` และยังใช้เฉพาะ reference หลัก 2 ไฟล์:

- `reference/law/prb60.md`
- `reference/law/rbb60.md`

ลำดับใช้งาน:

```powershell
python scripts\pasadu\build_index.py
python scripts\pasadu\route_query.py "มาตรา 56 กล่าวถึงอะไร"
python scripts\pasadu\retrieve.py "วิธีเฉพาะเจาะจงใช้กรณีใด" --limit 5
python scripts\pasadu\answer_context.py "คณะกรรมการตรวจรับพัสดุต้องดูจากข้อไหน"
python scripts\pasadu\cite_check.py --text "อ้างอิง: reference/law/prb60.md มาตรา 56"
python scripts\pasadu\eval_queries.py
```

หน้าที่หลัก:

- `build_index.py` แตกไฟล์กฎหมายเป็น chunks ตาม `มาตรา` และ `ข้อ`
- `route_query.py` เลือกว่าจะค้น `prb60.md`, `rbb60.md`, หรือทั้งสองไฟล์
- `retrieve.py` คืนตัวบทที่เกี่ยวข้องพร้อม citation
- `answer_context.py` รวม `pasadu.md` + คำถาม + ตัวบทที่ค้นเจอ เพื่อส่งต่อให้ chatbot
- `cite_check.py` ตรวจว่า citation ที่ AI ตอบมีอยู่จริงใน index
- `eval_queries.py` รัน smoke eval สำหรับ routing/retrieval

### Routing policy ปัจจุบัน

- ถ้าผู้ใช้ถามเจาะ `มาตรา`, `พรบ.`, `พ.ร.บ.`, หรือ `พระราชบัญญัติ` ให้ค้น `prb60.md` ก่อน และ fallback ไป `rbb60.md` เมื่อไม่พบ
- ถ้าผู้ใช้ถามเจาะ `ข้อ` หรือ `ระเบียบ` ให้ค้น `rbb60.md` ก่อน และ fallback ไป `prb60.md` เมื่อไม่พบ
- ถ้าคำถามทั่วไปไม่ได้เจาะแหล่งอ้างอิง ให้ค้น `rbb60.md` ก่อน เพราะการปฏิบัติงานยึดระเบียบเป็นหลัก แล้วใช้ `prb60.md` ประกอบเมื่อจำเป็น
- ยกเว้นกลุ่มบริหารสัญญา เช่น บริหารสัญญา บอกเลิกสัญญา ตกลงยกเลิกสัญญา แก้ไขสัญญา เปลี่ยนแปลงสัญญา งดหรือลดค่าปรับ หรือขยายเวลาทำการ ให้เริ่มอ่าน `prb60.md` ก่อน เว้นแต่ผู้ใช้ถามเจาะว่าเป็น `ระเบียบข้อใด`
- สำหรับคำถามซับซ้อน chatbot ควรถามผู้ใช้ก่อนว่าต้องการ “ตอบตามตัวบทเท่านั้น” หรือ “ตอบเชิงปฏิบัติโดยอ้างคู่มือ/แนววินิจฉัยประกอบ” เมื่อมี reference ประเภทอื่นเพิ่มในอนาคต
