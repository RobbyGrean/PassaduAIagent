# Pasadu Agent Usage Guide

เอกสารนี้อธิบายวิธีใช้งาน Pasadu ในฐานะ AI assistant/skill สำหรับคำถามด้านการจัดซื้อจัดจ้างและการบริหารพัสดุภาครัฐ โดยเน้นคำถามสำคัญข้อหนึ่ง:

> เวลาเปิดแชทใหม่ ต้องพิมพ์ `/pasadu` ทุกครั้งไหม?

คำตอบสั้นคือ **ไม่จำเป็นต้องพิมพ์ `/pasadu` ทุกครั้ง** ถ้าคำถามมีบริบทด้านพัสดุชัดพอ แต่การพิมพ์ `/pasadu` หรือใส่คำว่า “เรื่องพัสดุ” ยังมีประโยชน์เมื่อคำถามกำกวมมาก

## ภาพรวมของระบบ

Pasadu มีส่วนประกอบหลัก 4 ชั้น:

1. `SKILL.md`
   เป็น entrypoint ของ skill ใช้บอก Codex/agent ว่าเมื่อไรควรเรียกใช้ Pasadu และต้องเริ่มจากไฟล์ใด

2. `pasadu.md`
   เป็น runtime policy หลักของคำตอบ กำหนด persona, กฎการอ้างอิง, routing policy, รูปแบบคำตอบ, และข้อห้าม

3. `reference/`
   เป็นแหล่งอ้างอิงจริง เช่น `reference/law/prb60.md` และ `reference/law/rbb60.md`

4. `scripts/pasadu/`
   เป็น retrieval layer สำหรับ route คำถาม, ค้นมาตรา/ข้อ, สร้าง answer context, และตรวจ citation

เมื่อถามคำถามด้านพัสดุ ระบบที่ดีควรไหลแบบนี้:

```text
คำถามผู้ใช้
  -> skill trigger หรือ explicit /pasadu
  -> อ่าน pasadu.md
  -> route ไป reference ที่เหมาะสม
  -> retrieve มาตรา/ข้อที่เกี่ยวข้อง
  -> ตอบพร้อม citation ที่ตรวจสอบได้
```

## ต้องใช้ `/pasadu` ทุกครั้งไหม

ไม่ต้องใช้ทุกครั้ง

Skill มี description ที่ครอบคลุมคำ trigger สำคัญอยู่แล้ว เช่น:

- การจัดซื้อจัดจ้าง
- พัสดุภาครัฐ
- พรบ.
- พ.ร.บ.
- พระราชบัญญัติ
- ระเบียบ
- มาตรา
- ข้อ
- วิธีจัดซื้อจัดจ้าง
- สัญญา
- หลักประกัน
- ตรวจรับ
- อำนาจอนุมัติ
- ร้องเรียน

ดังนั้นในแชทใหม่ ถ้าถามว่า:

```text
วิธีเฉพาะเจาะจงใช้กรณีใด
```

หรือ:

```text
คณะกรรมการตรวจรับพัสดุมีหน้าที่อะไร
```

หรือ:

```text
การแก้ไขสัญญาต้องดูมาตราไหนก่อน
```

ระบบควรเข้าใจว่าเป็นคำถามด้าน Pasadu และใช้ skill ได้โดยไม่ต้องพิมพ์ `/pasadu`

## เมื่อไรควรพิมพ์ `/pasadu`

ควรใช้ `/pasadu` เมื่ออยากบังคับให้ agent เข้าโหมดพัสดุทันที โดยเฉพาะกรณีที่คำถามกำกวม เช่น:

```text
/pasadu แบบนี้ทำได้ไหม
```

หรือ:

```text
/pasadu กรณีนี้ต้องทำอย่างไรต่อ
```

ถ้าไม่ใส่ `/pasadu` คำถามแบบนี้มีความเสี่ยง เพราะคำว่า “แบบนี้” หรือ “กรณีนี้” ไม่มีสัญญาณชัดว่าเป็นเรื่องพัสดุ กฎหมาย ระเบียบ หรือสัญญาจัดซื้อจัดจ้าง

## ไม่ใช้ `/pasadu` แต่ควรใส่บริบทอย่างไร

ถ้าไม่อยากพิมพ์ `/pasadu` ให้ใส่บริบทสั้น ๆ แทน เช่น:

```text
เรื่องพัสดุ แบบนี้ทำได้ไหม
```

```text
กรณีจัดซื้อจัดจ้างแบบนี้ต้องใช้วิธีไหน
```

```text
ตามระเบียบพัสดุ คณะกรรมการตรวจรับต้องทำอะไรบ้าง
```

```text
ในงานจ้างก่อสร้าง ถ้าจะแก้ไขสัญญาต้องเริ่มดูตรงไหน
```

บริบทสั้น ๆ แบบนี้เพียงพอให้ agent รู้ว่าควรใช้ Pasadu


```text

```

```text

```

```text

```

```text

```

```text

```

คำถามเหล่านี้กำกวมเกินไปถ้าอยู่ในแชทใหม่:


## ความแตกต่างระหว่าง `/pasadu`, trigger อัตโนมัติ, และบริบทสั้น

| วิธีถาม | เหมาะเมื่อไร | ข้อดี | ข้อควรระวัง |
| --- | --- | --- | --- |
| `/pasadu ...` | ต้องการบังคับใช้ skill | ชัดที่สุด | อาจไม่จำเป็นถ้าคำถามชัดอยู่แล้ว |
| ถามตรงด้วยคำพัสดุ | คำถามมีคำ trigger เช่น ระเบียบ มาตรา ตรวจรับ | สั้นและเป็นธรรมชาติ | ถ้าคำถามสั้นมาก อาจยังไม่ชัด |
| ใส่บริบทสั้น เช่น “เรื่องพัสดุ...” | คำถามกำกวมแต่ไม่อยากใช้ slash | ชัดพอและอ่านง่าย | ต้องใส่บริบทให้เห็นว่าเป็นเรื่องพัสดุ |

## Routing policy ปัจจุบัน

Pasadu ไม่ควรอ่านกฎหมายทั้งเล่มทุกครั้ง แต่ต้อง route ก่อน retrieve

### 1. Default: ระเบียบก่อน

ถ้าผู้ใช้ถามทั่วไปโดยไม่ได้เจาะว่าเป็น พ.ร.บ. หรือระเบียบ ให้ค้น `reference/law/rbb60.md` ก่อน เพราะการปฏิบัติงานประจำวันยึดระเบียบเป็นหลัก

ถ้าไม่พบตัวบทที่เกี่ยวข้อง จึง fallback ไป `reference/law/prb60.md`

ตัวอย่าง:

```text
วิธีเฉพาะเจาะจงต้องทำอย่างไร
```

ควรเริ่มจาก:

```text
reference/law/rbb60.md
```

### 2. ถามเจาะ พ.ร.บ./มาตรา: พ.ร.บ. ก่อน

ถ้าผู้ใช้ถามด้วยคำว่า:

- พรบ.
- พ.ร.บ.
- พระราชบัญญัติ
- มาตรา

ให้ค้น `reference/law/prb60.md` ก่อน

ตัวอย่าง:

```text
มาตรา 56 กล่าวถึงอะไร
```

ควรเริ่มจาก:

```text
reference/law/prb60.md
```

### 3. ถามเจาะระเบียบ/ข้อ: ระเบียบก่อน

ถ้าผู้ใช้ถามด้วยคำว่า:

- ระเบียบ
- ข้อ

ให้ค้น `reference/law/rbb60.md` ก่อน

ตัวอย่าง:

```text
ระเบียบข้อไหนพูดถึงการแก้ไขสัญญา
```

แม้คำว่า “แก้ไขสัญญา” ปกติจะอยู่ในกลุ่มที่ต้องดู พ.ร.บ. ก่อน แต่คำถามนี้เจาะว่า “ระเบียบข้อไหน” จึงต้องเคารพเจตนาผู้ใช้และเริ่มที่ `rbb60.md`

### 4. กลุ่มบริหาร/แก้ไข/เลิกสัญญา: พ.ร.บ. ก่อน

สำหรับคำถามที่เกี่ยวกับ:

- บริหารสัญญา
- บอกเลิกสัญญา
- ตกลงยกเลิกสัญญา
- แก้ไขสัญญา
- เปลี่ยนแปลงสัญญา
- งดหรือลดค่าปรับ
- ขยายเวลาทำการ

ให้เริ่มค้น `reference/law/prb60.md` ก่อน เว้นแต่ผู้ใช้ถามเจาะว่าเป็นระเบียบหรือข้อ

เหตุผลคือกลุ่มนี้มักเกี่ยวกับอำนาจและหลักกฎหมายในระดับ พ.ร.บ. ก่อน แล้วจึงค่อยดูวิธีปฏิบัติตามระเบียบ

## คำถามซับซ้อนต้องถามผู้ใช้ก่อนหรือไม่

ต้องถามเมื่อคำถามมีแนวตอบได้หลายระดับ เช่น:

- ตอบตามตัวบทกฎหมายอย่างเดียว
- ตอบเชิงปฏิบัติสำหรับเจ้าหน้าที่
- ตอบพร้อมแนวคำวินิจฉัย หนังสือเวียน คู่มือ หรือ checklist

ในสถานะปัจจุบัน repo มี reference หลักคือ พ.ร.บ. และระเบียบ แต่มีแผนจะเพิ่ม:

- หนังสือเวียน
- คู่มือ e-GP/ECPP
- คำวินิจฉัย
- FAQ
- ตัวอย่างเอกสาร
- checklist

ดังนั้นถ้าคำถามซับซ้อน agent ควรถามก่อนว่า:

```text
ต้องการให้ตอบแบบใด:
1. ตอบตามตัวบทเท่านั้น
2. ตอบเชิงปฏิบัติโดยอ้างคู่มือ/แนววินิจฉัยประกอบ
```

แต่ถ้าคำถามเป็นคำถามตรง เช่น:

```text
มาตรา 56 คืออะไร
```

หรือ:

```text
ข้อ 78 ว่าอย่างไร
```

ไม่ควรถามกลับเรื่องโหมดคำตอบ ควร retrieve และตอบทันที

## ลำดับความน่าเชื่อถือของ reference

ปัจจุบัน repo ใช้ reference หลัก 2 ไฟล์:

1. `reference/law/prb60.md`
2. `reference/law/rbb60.md`

เมื่อมี reference เพิ่มในอนาคต ต้องแยกหน้าที่ของแหล่งข้อมูลให้ชัด:

| ประเภท reference | บทบาท |
| --- | --- |
| พ.ร.บ. | หลักกฎหมาย อำนาจ ขอบเขตใหญ่ |
| ระเบียบ | วิธีปฏิบัติประจำวัน ขั้นตอน รายละเอียด |
| หนังสือเวียน | แนวปฏิบัติหรือการตีความของหน่วยงาน |
| คู่มือ e-GP/ECPP | วิธีใช้งานระบบหรือ workflow เชิงระบบ |
| คำวินิจฉัย | แนววินิจฉัยประกอบกรณีเฉพาะ |
| FAQ | คำอธิบายหรือแนวตอบเบื้องต้น |
| ตัวอย่างเอกสาร | ตัวอย่างรูปแบบ ไม่ใช่ตัวบท |
| checklist | เครื่องมือช่วยตรวจ ไม่ใช่ฐานอำนาจ |

กฎสำคัญ:

- ห้ามถือว่าคู่มือ หนังสือเวียน FAQ ตัวอย่างเอกสาร หรือ checklist สูงกว่า พ.ร.บ. หรือระเบียบ
- ถ้าใช้เอกสารสนับสนุน ต้องบอกชัดว่าเป็น supporting guidance
- ถ้าแหล่งอ้างอิงขัดกัน ต้องชี้ให้เห็นว่าขัดกันตรงไหน และไม่สรุปเกินตัวบท

## ความสัมพันธ์ระหว่างไฟล์สำคัญ

### `SKILL.md`

ใช้บอก agent ว่า:

- เมื่อไรต้องใช้ Pasadu
- source of truth อยู่ที่ repo ไหน
- ต้องอ่าน `pasadu.md`
- มี retrieval scripts อะไรบ้าง
- routing policy ระดับ skill คืออะไร

### `pasadu.md`

ใช้เป็น runtime policy ที่ถูกส่งเข้า answer context จริง จึงต้องมี:

- บทบาทผู้ช่วย
- ขอบเขตความรู้
- หลักการตอบ
- routing policy
- กฎ citation
- กฎห้ามทำ
- รูปแบบคำตอบ
- การถามกลับ
- วิธีจัดการความไม่แน่นอน

### `scripts/pasadu/`

ใช้ทำให้ policy ทำงานจริง:

- `build_index.py`: แตกเอกสารเป็น chunks
- `route_query.py`: เลือก source หลักและ fallback
- `retrieve.py`: ค้นมาตรา/ข้อที่เกี่ยวข้อง
- `answer_context.py`: รวม policy + คำถาม + reference ที่ค้นเจอ
- `cite_check.py`: ตรวจว่า citation มีจริง
- `eval_queries.py`: smoke test ว่า routing ยังถูก

## ตัวอย่าง workflow ในแชทใหม่

### กรณีไม่ต้องใช้ `/pasadu`

ผู้ใช้ถาม:

```text
วิธีเฉพาะเจาะจงใช้กรณีใด
```

Agent ควร:

1. เห็นว่าเป็นคำถามจัดซื้อจัดจ้าง
2. ใช้ Pasadu
3. อ่าน `pasadu.md`
4. route ไป `rbb60.md`
5. retrieve ข้อที่เกี่ยวข้อง
6. ตอบพร้อม citation

### กรณีควรใช้ `/pasadu` หรือเพิ่มบริบท

ผู้ใช้ถาม:

```text
ทำได้ไหม
```

คำถามนี้ไม่ชัด Agent อาจไม่รู้ว่าเป็นเรื่องพัสดุ

ควรถามเป็น:

```text
/pasadu ทำได้ไหม
```

หรือ:

```text
เรื่องพัสดุ ทำได้ไหม
```

### กรณีต้องถามข้อมูลเพิ่ม

ผู้ใช้ถาม:

```text
ใช้วิธีเฉพาะเจาะจงได้ไหม
```

Agent อาจต้องถามเพิ่ม เช่น:

```text
ยังตอบให้ชัดไม่ได้ เพราะข้อมูลสำคัญยังขาดอยู่ ขอถามเพิ่ม:
1. เป็นงานซื้อ งานจ้าง งานก่อสร้าง หรือจ้างที่ปรึกษา
2. วงเงินงบประมาณหรือราคากลางเท่าไร
3. เหตุผลที่จะใช้วิธีเฉพาะเจาะจงคืออะไร
```

## กฎสั้นสำหรับผู้ใช้

ถ้าคำถามมีคำว่า `จัดซื้อจัดจ้าง`, `พัสดุ`, `ระเบียบ`, `มาตรา`, `ข้อ`, `ตรวจรับ`, `สัญญา` ไม่ต้องพิมพ์ `/pasadu`

ถ้าคำถามสั้นมากหรือกำกวม ให้พิมพ์ `/pasadu` หรือขึ้นต้นว่า “เรื่องพัสดุ...”

ถ้าต้องการคำตอบแบบมีน้ำหนักเชิงปฏิบัติ ให้บอกเพิ่มว่า:

```text
ขอทั้งตัวบทและแนวปฏิบัติ
```

ถ้าต้องการคำตอบแคบที่สุด ให้บอกว่า:

```text
ตอบตามตัวบทเท่านั้น
```

## กฎสั้นสำหรับ agent

1. ถ้าคำถามมี trigger ด้านพัสดุ ให้ใช้ Pasadu แม้ผู้ใช้ไม่พิมพ์ `/pasadu`
2. อ่าน `pasadu.md` ก่อนตอบ
3. ใช้ retrieval scripts ถ้าพร้อมใช้งาน
4. route ก่อน retrieve ห้ามอ่านทั้งเล่มโดยไม่จำเป็น
5. citation ต้องมีไฟล์และเลขมาตรา/ข้อ
6. ถ้าไม่พบ citation จริง ให้บอกว่าไม่พบ
7. คำถามกำกวมให้ถามกลับ ไม่เดา
8. คำถามซับซ้อนให้ถามโหมดคำตอบก่อน เว้นแต่เป็นคำถามขอตัวบทโดยตรง
